# Escaping the assembly CAI seed

Measured on this tree, after v2.9.3. Same host, weights, and checker as
`docs/benchmarks/v2.9.3-optimization-quality.md`. That note is the before
column. This note does not move those rows.

The question was the one that note left open. Under assembly constraints
(GC windows and unique 12-mers), single-objective CAI sat on the one CDS
seed repair built, and extra generations did not raise it. Seed 7 was not
always the best job seed: waaS seed 11 reached 0.9220206722508919 against
0.9173459052341192 at seed 7. On rpsL the design sat 0.0038104428470379093
below a sequence that fails one 12-mer.

## What was stuck

Tier 1 still refuses those rules (`CF-SRCH-017`). The dynamic program
cannot carry a GC window or a scattered 12-mer. `potts_guided` and
`block_gibbs` stay off without an epistasis model (`CF-SRCH-001`,
`DEP-SRCH-005`). The mix that runs is uniform synonymous and
violation-directed. Once the seed is feasible, violation-directed has
nothing to repair.

Seed repair was deterministic and stopped at the first feasible attempt.
That attempt is the weight-ordered tie-break on the most-frequent-codon
assignment. The low-index tie-break, and the input as a second start, were
not built. On waaS the weight-ordered start is feasible, so the low-index
start — the one whose CAI matches the old seed-11 design before any
further climb — never ran. The job seed does not enter this function.
Seeds 7 and 11 were different only in the NSGA draws after that shared
seed. One of those draws found a better CDS. The default seed did not.

Local CAI ascent (`DEP-SRCH-018`) only pairs a hot codon with a neighbour
within four positions. A 12-mer's other copy, and a GC window of 50 nt,
can sit further away.

## What changed

Two changes, both inside seed resolution, both deterministic, neither
reading the job seed.

`DEP-SRCH-021`. After the local pairs, up to six passes try every counted
codon that is not already on its heaviest synonym. The heavier codon is
kept when it is feasible and the geometric mean rises. When it is not, the
codons that overlap the new violation are collected nearest-first, capped
at 48: pattern spans, GC windows that overlap the edit, and the other
copies of an over-limit k-mer. A single partner is tried when the sum of
log-weights stays positive. If no single partner is feasible, pairs among
the six closest of those sites are tried, capped at 48 trials. The kept
edit is the higher CAI, then fewer partners, then the lower site and codon
index. A counted weight of 0 is rejected, because the geometric mean
becomes 0.

`DEP-SRCH-022`. All four attempts are scored: weight order then low index,
and within each the most-frequent assignment then the input. A feasible
result beats an infeasible one. Two feasible results keep the higher CAI,
then fewer committed edits. The first feasible attempt does not end the
search.

No tier-3 operator was added. Uniform synonymous, on the CDS this resolver
now returns, does not raise the assembly CAI in the table below between
generations 0 and 4. The reported sequence is the seed.

## Command

From the repository root, after `make build`. Host
`escherichia_coli:511145/MG1655`, translation table 11, objective
`usage.cai`, ribosomal weights
`examples/mg1655_ribosomal_usage.json`, constraints
`benchmarks/validation/constraints_assembly.json`, seed 7, stagnation
window 21. Budget `fast` with generations 0 is tier 1 and tier 2. Budget
`standard` with generations 4 adds tier 3. The rows below are
`tools/benchmark_common.run_codonforge` with those arguments. CAI is
`benchmarks/validation/cai_independent.py`, and it matches `usage.cai`
on every row. Every design passes `constraint_violations` for the
constraint set it was built under.

`--cds` is the coding sequence, not a path. The CLI default seed is 0
and the default stagnation window is 8. A run of 4 generations stops at
generation 4 under either window. Seed 0 and seed 7 return the same waaS
CDS (`d227b303a3c477cea7f5ed35c3a0fbcb783cb9169fa38a3737e0fe7699419f16`,
CAI 0.9259163095438141), because the repair does not read the job seed
and tier 3 did not replace it.

```sh
.venv/bin/python - << 'PY'
import sys
from pathlib import Path
sys.path.insert(0, "tools")
import benchmark_common as common
from codonforge.modelreg import ArtifactStore

genes = {item["gene"]: item for item in common.load_genes()}
constraints = next(item for item in common.load_constraint_sets() if item["name"] == "assembly")
weights = common.load_weights()
profile = common.host_profile(weights)
row = common.run_codonforge(
    genes["waaS"]["cds"],
    constraints["document"],
    profile,
    common.profile_digest(profile),
    ArtifactStore(Path("/tmp/codonforge-v294")),
    budget="standard",
    seed=7,
    generations=4,
    stagnation_window=21,
    job_id="waaS-assembly",
)
print(common.independent_cai(row["cds"], weights)["cai"])
print(row["candidates"][0]["sha256"])
PY
```

does not reach the low-index CDS. The two basins are different repairs,
not a missed neighbour of the first one.
