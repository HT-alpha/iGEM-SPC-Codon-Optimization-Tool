# v2.5.0 performance

Measured on commit `386cebd` (branch `cursor/frontend-guided-suite-88de`) on 16 October 2026. The machine was a 4-vCPU Intel Xeon. ViennaRNA 2.7.2 was installed in the virtualenv. `python -m dna_design_suite.cli.main --version` prints `0.1.0`, which is the package version; this note is about the v2.5.0 tree.

No product code was changed for these runs.

## What was asked of the tool

Every design used host `escherichia_coli:511145/MG1655`, the bundled ribosomal table `examples/mg1655_ribosomal_usage.json`, and the bundled constraint file `examples/rpsL_constraints.json`. That file has an empty `constraints` array and `repair_policy.lamarckian: true`. Translation table 11, which is the CLI default. The objective was `usage.cai` unless a run says otherwise. `--generations` was left unset, so the CLI default of 12 was used. Status documents for `standard` and `exact` report `max_generations` 12.

Budgets were `fast`, `standard` (the CLI default), and `exact`. Seeds were 7 and 11. Seed 7 was run a second time for every CAI-only configuration. Wall time is the process time around the CLI, or, for the API, from the POST until the job reached a terminal state.

`usage.cai` and feasibility come from the job documents. GC content is `(G+C)/length` of the CDS, counted from the sequence. The accessibility penalty is the ViennaRNA value the tool attaches. On a CAI-only job it is in `objective_detail`, not in `objective_vector`. The structure-objective run labels that axis `minimize`. A larger penalty is the worse direction on that axis. `percentile_vs_native` was null on every front that was inspected.

## CAI-only results

Every accepted CAI-only job succeeded. The protein was unchanged and the nucleotide length was unchanged. The recommended candidate's `usage.cai` was 1.0, and scoring that CDS again with `score_sequences` also returned 1.0. `constraint_report.feasible` was true and `violations` was empty. With this constraint file, that means the empty rule list was satisfied. It does not mean a restriction site or a GC window was checked.

For every gene, seed 7, seed 11, `fast`, `standard`, and `exact` returned the same CDS and the same candidate id. The second seed-7 run matched the first, including the candidate id. The five API jobs (`POST /v1/jobs` on `python -m dna_design_suite.api --port 8091`, bearer `t_localdemo01`) returned the same CDS and the same job id as the matching CLI run.

`fast` runs tier 1 and tier 2. `standard` and `exact` also run tier 3, which stopped at generation 9 of 12. `exact` lists `decision` as `skipped`. The reported origin stayed `tier1_dp` for five genes and `tier2_block_ca` for mCherry. Tier 3 did not replace that candidate. Wall time barely moved when the budget grew.

CLI times below are the first seed-7 run. Seed 11 and the repeat stayed in the same band: about 0.24–0.31 s for the genes under 900 nt, and 0.46–0.52 s for lacZ.

Warnings on every CAI-only success:

- `CF-SRCH-001` stage `operators`, subjects `potts_guided` and `block_gibbs`. Both say the operator is not available because no epistatic context model is registered, and that the remaining operator weights were renormalized.
- `CF-LAND-013` stage `landscape`, subject `structure.local_accessibility`. The title is "A term was computed for reporting only, not optimized against". ViennaRNA did run for the candidate. The number is in `objective_detail` and is absent from `objective_vector`.

`exact` adds `CF-ORCH-006` stage `tier_plan`, subject `decision`: the exact budget plans a decision tier this build does not run.

The untrimmed 720 bp BBa_E0040 part exited 2 in 0.200 s with `CF-SEQ-003`: codon 238 (`TAA`) is a stop in translation table 11. The part ends with two stop codons, and only the last codon may be a stop.

## Plain summary

On a single CAI objective, against this ribosomal table, the build is fast and repeatable out to a 1025-codon gene. lacZ is 8.2 times as long as rpsL. The warm API time was 0.063–0.088 s for rpsL and 0.260 s for lacZ. The cold CLI time was about 0.25 s and about 0.46–0.52 s. Raising the budget from `fast` to `standard` or `exact` did not change the sequence and did not add a meaningful amount of time, because the reported candidate already had CAI 1.0 before tier 3, and tier 3 stopped at generation 9.

CAI 1.0 here means every scored codon has relative adaptiveness 1 in the supplied table. It is not an independent measurement of expression. `AGG` and `TAG` have weight 0 in this table. mCherry's input CAI is 0 because of one in-frame `AGG`. The design removes that codon, keeps the protein, and the score becomes 1. The other five inputs have no `AGG` or `TAG`, and their CAI still rises to 1.0 by synonymous replacement. mCherry is also the only gene whose reported candidate came from tier 2 rather than tier 1.

The constraint result is not evidence about sites or GC windows. The example constraint file contains no rules.

Structure is reported beside a CAI-only design, with the warning that it did not steer the search. Putting it in the objective list does not fill the recommended candidate's structure score. Those jobs take several seconds instead of a fraction of a second, return a larger front, and still recommend the CAI winner. One fold of lacZ is about 0.2 s, so the extra seconds are the population, not a single fold.

Two practical surprises for an iGEM part: a registry CDS that ends in two stop codons is rejected with `CF-SEQ-003`, and every CLI run prints a `RuntimeWarning` from `python -m dna_design_suite.cli.main` before the result.

These runs do not stress multi-objective tradeoffs, non-empty constraint sets, or genes longer than lacZ. They also do not include sfGFP, EGFP, lacZ alpha, T7 RNA polymerase, or any BioAegis gene.
