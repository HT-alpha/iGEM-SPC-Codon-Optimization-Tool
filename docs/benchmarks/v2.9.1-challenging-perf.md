# DNA Design Suite v2.9.1 — challenging-sequence timings

Measured on this tree after the v2.9.1 search and fold changes, including
the operon ledger edit below. Host `escherichia_coli:511145/BL21`. Codon
weights `examples/mg1655_ribosomal_usage.json`. Translation table 11.
Seed 7. Stagnation window 21. Segment 2. ViennaRNA 2.7.2.

Sweep budget is `fast`. In-core jobs use generations 0, so the run is tier 1
and tier 2. Structure is L0, so those jobs use generations 2. Otherwise the
axis is never scored. The four slowest design jobs were run again at budget
`standard`, generations 4.

Each row is its own process. Peak RSS is `ru_maxrss` for that process,
including the interpreter and the loaded extension. Linux reports kilobytes.
There were no timeouts and no crashes. Every design translated to the input
protein and had zero actionable violations under the constraint set it was
given.

The raw rows are `v2.9.1-challenging-sweep.json` and
`v2.9.1-challenging-standard.json`.

```sh
.venv/bin/python tools/challenging_perf.py --suite sweep --out /tmp/cf-sweep.json
.venv/bin/python tools/challenging_perf.py --suite standard \
  --from /tmp/cf-sweep.json --out /tmp/cf-standard.json
```

Assembly is `benchmarks/validation/constraints_assembly.json` (GC windows,
homopolymers, repeats, and the Golden Gate / BioBrick sites). Golden Gate
and BioBrick are `examples/golden_gate.json` and `examples/biobrick_rfc10.json`.
The synthetic primer flanks are `ACGT` repeated, 300 nt on each side. They
are not a biological sequence. The repeat makes a dimer below −9 kcal/mol,
so the recommended pair is refused. The same gene with its own CDS as the
flanks is not refused.

`aceB` with CAI and burden, and no assembly rules, scores CAI
0.9530633221854043 with no in-frame `AGG`. The CAI-only run of the same CDS
scores 1.0. Burden can still reject a step that would raise CAI once the
zeros are gone. That is the acceptance rule, not a zero-weight codon left
in the design.

On budget `fast` the progress list names tier 1 and tier 2. Structure jobs
in this sweep still folded: yeeJ recorded 1 full fold, 21 local codon edits,
and 12 repeated-sequence hits. Budget `standard` names tier 3 as well.

## Operon ledger

Before this edit, every synonym in a joint pass recounted both CDS and
rebuilt the demand vector. On lacZ plus thrA that pass took 9.185 s. The
same call after the edit takes 1.632 s. The joint cost and the swap counts
are the same. A one-codon edit of the count vector matches
`_weighted_counts` on the rewritten sequences, including a flux other than 1.
The reported joint cost is still that full recount.
