# DNA Design Suite v2.9.2 — where the time goes

Measured on this tree with `maturin develop` (`profile.dev`, `opt-level = 1`),
the same build `make build` produces and the same one behind the v2.9.1
challenging-sequence note. Host `escherichia_coli:511145/BL21`. Codon weights
`examples/mg1655_ribosomal_usage.json`. Translation table 11. Seed 7.
ViennaRNA 2.7.2 for the structure rows. Each row is its own process. Peak
RSS is `ru_maxrss` for that process, including the interpreter. Linux reports
kilobytes.

The raw rows are `v2.9.2-profile-rows.json`.

```sh
.venv/bin/python tools/profile_suite.py --suite all --out /tmp/cf-profiles.json
```

`CF_SEED_PROFILE=1` prints inclusive counters from `resolve_feasible_seed`.
`CF_PRIMER_PROFILE=1` prints counters from `primer_search`. cProfile attributes
the Python side and the PyO3 boundary. A Rust stage is one builtin call on
that side; the counters name the functions inside it.

Scoring did not change. Every vector below that also appears in
`v2.9.1-challenging-perf.md` is the same number. The yeeJ primer document
for 300 nt CDS flanks is the same bytes (SHA-256
`5f1fa115bcefde58d0c3d92a35e7adbc5fcbf04bf78b6efe43bf75f946aa149f`).

feasibility verdict.

Empty-constraint CAI is tier 1. The seed does not run, because the DP can
carry that objective. Wall time above the tier sum is process start plus the
front. On a CAI-only yeeJ assembly job, cProfile puts 1.774 s in the single
builtin `resolve_feasible_seed`, 0.287 s in `search_tier2_polish`, 0.369 s in
`explain_baseline`, and 0.446 s in one ViennaRNA `pfl_fold_up` inside
`structure_diag.annotate`. That fold is the `CF-LAND-013` diagnostic: the
engine is installed, so the front reports accessibility for the candidate
even though the search did not rank on it. It is one full fold of 7077 nt,
about 0.063 ms/nt.

`explain_baseline` (`explain_deviations`) substitutes the most-frequent codon
back at every position that differs and calls `ConstraintChecker::check` for
each one. yeeJ's repaired seed differs in hundreds of positions, and the
assembly set contains a 12-mer rule, so `influence_radius_nt` is `None` and
`check_region` cannot be used. 0.370 s on yeeJ, 0.060 s on rpoB.

Burden without assembly constraints moves time into tier 2 (rpoB 0.110 s),
not the seed. The rpoB vector matches the v2.9.1 row.

## Primer design

Filters already run cheap-first. On one yeeJ window set (flank 300, 4472
windows): GC 0.00018 s (4472 calls), homopolymer 0.00030 s (4246 calls, the
rest already rejected), SantaLucia Tm 0.0090 s (4063 calls). Product length
is checked before any pair ΔG (1600 calls, 0.00005 s). What used to dominate
was doing hairpin, self-dimer, and Tm again for every one of the 40×40 pairs.
Hairpin and self-dimer depend only on the oligo. Tm was already stored on
the oligo from the prefilter.

After computing those once per survivor (80 oligos, not 1600 pairs) and
comparing Pareto objectives in place (`constraint_dominance` was allocating
two `Vec<f64>` per comparison, about 1.3 million comparisons at the cap):

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| yeeJ, region 1000, flank 50 | 0.005 s | 0.003 s | 72, not truncated | 54039 | 0.0001 s | 0.0011 s |
| yeeJ, region 1000, flank 100 | 0.140 s | 0.057 s | 1600, truncated | 52697 | 0.019 s | 0.022 s |
| yeeJ, region 1000, flank 200 | 0.137 s | 0.060 s | 1600, truncated | 54030 | 0.020 s | 0.022 s |

cProfile on the 6477 nt region shows one builtin `primer_search` at 0.069 s
of a 0.070 s Python call. There is no Python hot path.

Cost scales with the number of pairs that reach ΔG, and that number is
capped at 40×40 once the flank is long enough to fill it (flank 100 already
truncates; flank 50 does not, and the run is 0.003 s). Region length barely
moves the clock (0.066 s at 300 nt, 0.072 s at 6477 nt) and does move the
response: each of the 20 returned pairs embeds `product_sequence`. 44 KB at
300 nt, 166 KB at 6477 nt. RSS for that row is 42468 KiB, against about
31000 KiB for the flank-50 row that never builds 1600 long amplicons.
`score_pair` still builds the amplicon string for every survivor, then the
rank keeps 20.

The synthetic-flank pair is still refused. The recommended yeeJ CDS-flank
pair is still `TGACCGACAAATATTATG` / `GAACTACAGTGGTTTAAA`, product 6843,
ΔG −1.283850000000001, not refused.

At the cap, the remaining pair time is hetero-dimer (1600 calls, 0.023 s)
plus the non-dominated sort (0.020 s). GC, homopolymer, Tm, and product
together are about 0.010 s.

## What shipped

1. `ConstraintChecker::check_patterns` and `Solver::pattern_hits`. Pattern
   trials no longer build the k-mer index or the GC windows. yeeJ
   `pattern_count` 17.919 s → 0.439 s.
2. Homopolymer excess is a cached total plus a delta on the runs that
   intersect the edited codon (`homo_after`). 34064 full scans, 0.815 s →
   0.002 s. The delta matches a full scan, including merges, in
   `homopolymer_delta_matches_a_full_scan_including_merges`.
3. Primer hairpin, self-dimer, and Tm are computed once per oligo after the
   top-40 truncation. Hetero-dimer stays per pair. The yeeJ primer JSON is
   byte-identical.
4. `pareto_dominance` compares the objective slices in place. Same `<` walk,
   no per-comparison allocation. Primer rank at the cap 0.068 s → 0.020 s.
   The same JSON hash.

Pinned so a later edit that moves an accept/reject fails: ribosomal-weight
assembly seeds for elastin, yagF, waaS, and yeeJ in
`crates/cf-constraints/tests/seed_assembly.rs`; the waaS CAI vector
`[0.9173459052341191]` and the yeeJ primer hash in
`python/tests/test_profile_identity.py`.

### Blocked on unmeasured biology, or not a defect

- `epistasis.dwell_deviation` stays `CF-LAND-001`. The dwell head is
  `not_fitted`. No timing work belongs on that path.
- Host catalogue, model catalogue, and `GET /v1/recalibrations` stay
  `CF-CLI-003`.
- No gene-copy number, s-value, or host-distance penalty.
- The CAI-only diagnostic fold (`structure_diag.annotate` → `pfl_fold_up`,
  0.444 s on yeeJ) is one reported accessibility value and the `CF-LAND-013`
  warning. Deleting it makes the front document smaller and drops a number
  the page shows. It is not search time. A batch fold API is `P2-05a` and
  is what would change tier 3, not this one call.
- Primer filter order does not need a reorder. GC and homopolymer already
  reject before SantaLucia Tm. Product length already rejects before
  hetero-dimer ΔG. There is no cheaper published reject in this suite that
  would drop a pair before that ΔG without changing which pairs exist.
