## What was broken

rpoC assembly, before this tree, returned `CF-SRCH-006` in 0.190 s.
Single-codon GC sweeps left windows outside the 50 nt band. K-mer repair
returns immediately while `gc_penalty` is above `1e-9`, so the cycle
stopped with both GC windows and repeated 12-mers still open. The stricter
stress set below was already feasible on rpoC, so a synonymous assembly
CDS existed and the failure was a search miss.

`DEP-SRCH-023`. After a cycle whose score does not fall, and only while
the seed is still infeasible, at most four pair edits run inside the first
outside GC window. A pair is kept when the offender count falls and
pattern hits do not rise. K-mer excess may rise, which is what lets the
next cycle's k-mer repair run. A seed that is already feasible breaks
before this branch. The in-loop NSGA repair operator is unchanged.

After the change, rpoC assembly succeeds. CAI 0.9593415607455033. SHA-256
`7e80dcaa96a48b33e0078568ff2d6e5638a3cdedc6d6b001d5401ebe66397ca7`. Zero
actionable violations. Wall 1.401 s, of which `resolve_feasible_seed` is
0.958 s. The regression test is
`test_rpoc_assembly_seed_is_feasible`. Skipping the branch returns
`CF-SRCH-006` again.

waaS under the stress set still returns `CF-SRCH-006` (0.078 s). The suite
records that as a best-effort row. The set is not a published feasibility
claim.

## What got faster

`is_feasible` on an `ACGT` construct used to treat a float GC penalty above
`1e-9` as a violation and re-scan every window. The penalty can sit in
`(0, 1e-9]` after incremental edits, and the scan was the dust. The
predicate is now the integer offender total, plus actionable k-mer excess,
plus the pattern count. The float penalty still drives the sweeps and the
progress score.

The before and after rows are the same harsh yeeJ seed, same call counts,
same CDS. Harsh means the assembly file plus `c_gc30` (30 nt, GC in
[0.35, 0.65]), `c_homo5` (any base, run at most 5), and `c_kmer10` (k = 10,
at most 2 occurrences, overlapping). `constraint_set_id` is
`cst_harsh_assembly`.

Ordinary assembly yeeJ is a different, already-feasible trajectory.
`is_feasible` there is 22823 calls: 0.029 s before this predicate change,
0.0011 s after. Seed wall stays about 1.96 s and the CDS stays
`72bd74389f99f3aba3dfcb5422c05c91db606adaacb65f67a5a80f881dc6e540`. The
wall win is the two-band seed, where the scan was a second.

The pair escape itself changes a seed that used to stall. Harsh yeeJ
before that escape was a different CDS, CAI 0.9664717080363605, SHA-256

`kmer_replace` (0.94 s) and `gc_delta` (0.36 s) are the remaining costs
inside `climb` on the harsh yeeJ seed. They were left in place. A GC range
tree was already rejected when `gc_delta` was the cheap term. Primer
ranking was left in place: the wide oligo pool below is 0.072 s.
