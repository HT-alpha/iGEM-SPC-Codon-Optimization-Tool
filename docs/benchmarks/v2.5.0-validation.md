## A. Independent CAI

Sharp & Li CAI is the geometric mean of relative adaptiveness over counted codons. Counted codons exclude stops and the single-codon families Met (`ATG`) and Trp (`TGG`), which is the set CodonForge scores. A counted codon of weight 0 makes the mean 0. A codon is a top synonym when its weight equals the maximum in its synonymous family, ties included. `CAI = 1` on a table means every counted codon is a top synonym of that table. The check `cai == 1.0` agreed with that codon count on every sequence below.

Two weight tables:

1. The bundled ribosomal table `examples/mg1655_ribosomal_usage.json` (`codon_usage.subset = user_supplied`). `AGG` and `TAG` have weight 0. The smallest positive weight is `0.002392`.
2. Kazusa *E. coli* K-12 taxid 316407, file `benchmarks/validation/kazusa/e_coli_316407.csv`, from Edinburgh-Genome-Foundry/python_codon_tables. The file stores genome-wide synonymous relative frequencies (Nakamura, Gojobori, and Ikemura, Nucleic Acids Research 2000;28:292). Weights here are frequency divided by the synonymous maximum. This is not Sharp & Li’s highly expressed reference set. That numeric table was not retrieved.

Host for the design reruns was `escherichia_coli:511145/MG1655`, objective `usage.cai`, budget `fast`, seed 7, empty constraints `examples/rpsL_constraints.json`, generations left at the CLI default of 12. Every CLI invocation printed `RuntimeWarning: 'codonforge.cli.main' found in sys.modules...` and the successful jobs still exited 0.

### mCherry input CAI of 0

BBa_J06504 contains one in-frame `AGG` at codon index 168 (arginine). `AGG` has ribosomal weight 0, and `TAG` is the other zero but it is a stop, so it is not counted. The geometric mean of a set that includes 0 is 0. That is Sharp & Li arithmetic, and it is what the product returns. It is also easy to misread: one codon zeros an otherwise ordinary gene. Replacing each 0 with `0.002392`, the smallest positive weight in the bundled table, gives `0.458413`. That figure is a sensitivity. It is not Sharp & Li, and it should not replace the reported CAI. The design output contains no `AGG` and scores 1.0 on this table, which shows the input 0 was that codon. A report of 0 should say that a zero-weight codon is present.

## B. Hard cases with a non-empty constraint set

Constraints in `benchmarks/validation/constraints_assembly.json`, all blocking, scope `cds`:

- GC fraction of every 50 nt window, step 1, inside 0.40 to 0.60 inclusive
- BsaI `GGTCTC`, BsmBI `CGTCTC`, EcoRI `GAATTC`, XbaI `TCTAGA`, SpeI `ACTAGT`, PstI `CTGCAG`, NotI `GCGGCCGC`, both strands, zero occurrences. A palindromic site is counted once
- homopolymer run longer than 6
- `AGGAGG` on both strands, as an internal Shine-Dalgarno motif
- any 12-mer that occurs more than once, overlaps counted

Seed 7, objective `usage.cai`, generations 12, budgets `fast` and `standard`. An independent counter and `codonforge feasibility` agreed on every CodonForge input, output, and most-frequent baseline in this section (`census_matches_product` true). The front’s `n_blocking_violations` field is 0 or 1. It is not a violation count. The counts below are the feasibility command and the independent counter.

Cryptic start-plus-stop is not a first-class rule. A separate probe, `constraints_cryptic_probe.json`, puts `AGGAGG[ACGT]{4,12}ATG` in a `custom_regex`. On the first 300 nt of yagF the feasibility command returned exit 0, 0 violations, and `undetectable: ["c_cryptic_start"]` in 0.215 s. An independent sense-strand count of that pattern is 0 for yagF, waaS, and the elastin-like CDS, and 1 for yeeJ. Those counts were not enforced.

Tm. ## D. What to do next, for an iGEM team

Rough size is small (a message, a preset, or a test), medium (a search or parsing change), or large (a new scientific path). The order is the order an iGEM team should do the work.

1. **Small. A failed design currently looks like an answer.** All eight constrained jobs exited 0 with `state: failed` and `CF-SRCH-006`, and the CDS in the result is the input. The tier rows stay `pending` even though the problem’s stage is `tier1`. Exit non-zero when the job failed, and show the CF code and the sentence in the table and on the page. Until that ships, read `status.state` and `status.problem`, not the exit code.

2. **Medium. GC windows and scattered repeats never reach a search.** `CF-SRCH-006` says the dynamic program cannot carry those rules and that repair should. In this run repair did not run: tier 2 and tier 3 stayed pending and the sequence did not change. DNA Chisel, given the GC, enzyme, homopolymer, and Shine-Dalgarno rules, returned translations with those counts at 0. Either run a repair or a later tier after `CF-SRCH-006`, or say on the page that a GC-window or k-mer rule stops the job at tier 1. Sliding 50 nt windows step by 1, which is what the checker does, produced 1596 violations on a 1968 nt gene. A student cannot tell a truly impossible GC target from a rule the search never tried.

3. **Small. Say what CAI 1.0 and CAI 0 mean next to the number.** 1.0 means every counted codon is a top synonym of the loaded table. The Kazusa genome-wide weights put those same CDS near 0.74–0.78. 0 means a counted codon has weight 0; mCherry’s input is one `AGG`. Show the codon. Keep the geometric mean. The floor `0.458413` is a sensitivity and should stay labelled as one. The bundled example constraint file is empty, so “feasible” on the rpsL demo does not mean an assembly rule was checked.

4. **Small. Preset the assembly rules, and mark rules that are not checked.** The constraint file used here is a reasonable Golden Gate / synthesis set. `custom_regex` for an SD-like motif upstream of `ATG` is reported `undetectable` and does not change feasibility. The page should say that, because a student who pastes the regex will otherwise believe cryptic starts were removed.

5. **Small. Clean primer input the same way on the API and the page, and name the bad base.** Lowercase is refused as `base a is not A, C, G or T`. `N` is refused as `bad base` with no index. A FASTA header left in the API sequence shifts the region by the header length; the page deletes non-ACGT characters and keeps the `G` from `GFP`, so the same paste is a different template. Strip a FASTA header, uppercase the rest, and if a base is illegal name it and its position.

6. **Small. The 3′ clamp is a column, not a rule.** The waaS reverse primer ends in T and was the recommended pair. Say “informational” next to the clamp, or refuse a pair whose 3′ base is A or T if that is the rule the team wants.

7. **Medium. Genome specificity is not checked.** The page already says so. For an iGEM part in a host genome, that is the usual next question after Tm and dimers. A local BLAST or an exact search against the host FASTA the user supplies would answer it. Shipping a genome is a separate choice.

8. **Small. The CLI warning on every run.** `python -m codonforge.cli.main` prints a `RuntimeWarning` about `codonforge.cli.main` already being in `sys.modules`, then continues and can still exit 0. It showed up on every design and on the refused double-stop GFP.

9. **Small. Registry parts that end in two stops.** Untrimmed BBa_E0040 is 720 bp and ends `TAATAA`. The refusal `CF-SEQ-003` is correct for a CDS with an internal stop. The message names codon 238. Offering “use the first stop” on the page would match the 717 bp sequence that does design.

10. **Large, after the items above. Accessibility as an objective.** These CAI jobs emit `CF-LAND-013`: ViennaRNA 2.7.2 evaluated `structure.local_accessibility` for the report, and the term is absent from the ranked vector. The performance note already measured structure-as-objective leaving the recommended axis unknown. Leave it documented until a batch path exists. Do not present the reported accessibility number as something the search optimized.

11. **Small test to lock item 1 and item 2.** The independent census matched `codonforge feasibility` on every sequence this round, so the checker is doing what its rules say. A test that submits the elastin-like CDS with `constraints_assembly.json` and expects either a changed CDS or a non-zero exit would have caught `CF-SRCH-006` exiting 0 with the input sequence. The human rare-codon case is still blocked until a CDS can be fetched from a host this environment can reach.
